Da planilha bagunçada ao modelo relacional

1FN, 2FN, 3FN e BCNF na prática, com SQL no PostgreSQL 16

1FN2FN3FNBCNFPostgreSQL 16

01 Introdução

Imagine uma pequena loja virtual que controla as vendas em uma planilha. Cada linha registra um produto vendido dentro de um pedido, e, para não perder nenhuma informação, alguém foi copiando junto os dados do cliente e do produto.

Pedido Data Cliente E-mail do cliente Cidade Produto Preço (R$) Qtd
101 03/03 Ana Souza ana@email.com Curitiba Caneca 25,00 2
101 03/03 Ana Souza ana@email.com Curitiba Camiseta 59,90 1
102 05/03 Bruno Lima bruno@email.com Foz do Iguaçu Caneca 25,00 1
103 08/03 Ana Souza ana@email.com Curitiba Chaveiro 9,90 3

Suponha que a Ana troque de e-mail. Na planilha, o e-mail dela aparece em três linhas, então vamos precisar corrigir as três. Com quatro linhas isso é fácil. Com quatro mil, alguém vai esquecer uma. A partir daí a loja passa a ter dois e-mails diferentes para a mesma cliente, e ninguém sabe dizer qual é o certo.

Chamamos de redundância essa repetição da mesma informação em mais de um lugar. E a redundância traz mais dois problemas além da correção em vários lugares: não conseguimos cadastrar algo novo sozinho, apagar algo pode apagar outra junto. Isso são as anomalias de atualização, inserção e exclusão: situações em que uma operação simples (alterar, incluir ou remover um dado) produz um resultado errado ou impossível por causa da forma como a tabela foi montada.

02 Conceitos

Chave primária é a coluna (ou grupo de colunas) que identifica cada linha; na planilha, é o par (Pedido, Produto). Chave estrangeira é uma coluna que aponta para a chave primária de outra tabela. Dependência funcional (A → B): sabendo A, sabemos B. Sabendo o produto, sabemos o preço. As formas normais são regras sobre essas dependências (KENT, 1983).

03 1FN: um valor por célula

Na Primeira Forma Normal, cada célula guarda um único valor, o valor atômico (GURU99, [s.d.]). Uma célula "Caneca, Camiseta" violaria a regra. Nossa planilha já está na 1FN.

04 2FN: dependência parcial

A 2FN é violada quando uma coluna fora da chave é "um fato sobre uma parte da chave" (KENT, 1983, tradução nossa): a dependência parcial. Data e Cliente dependem só de Pedido; Preço, só de Produto. Separamos pedido, produto e item_pedido.

05 3FN: dependência transitiva

A 3FN é violada quando uma coluna fora da chave é "um fato sobre outra coluna fora da chave" (KENT, 1983, tradução nossa). O e-mail depende do cliente, que depende do pedido: uma dependência transitiva. Separamos o cliente, como faz a apostila do IFPR (WAUKE, [s.d.]): 

-- PostgreSQL 16 | completo em sql/04_3fn.sql
CREATE TABLE cliente (
  id_cliente SERIAL PRIMARY KEY,
  nome   TEXT NOT NULL,
  email  TEXT NOT NULL UNIQUE,
  cidade TEXT NOT NULL
);
CREATE TABLE pedido (
  id_pedido  INT PRIMARY KEY,
  data       DATE NOT NULL,
  id_cliente INT NOT NULL REFERENCES cliente -- chave estrangeira
);

O e-mail da Ana fica em uma linha:

UPDATE cliente SET email = 'ana.souza@email.com' WHERE id_cliente = 1;

E cancelar o pedido do Bruno não apaga o cadastro dele.

06 BCNF: quando a 3FN não basta

Nos horários de um curso, cada professor dá uma só disciplina:

Aluno Disciplina Professor
Ana Banco de Dados Marta
Bruno Banco de Dados Marta
Ana Redes Paulo

A chave é (Aluno, Disciplina) e a tabela está na 3FN, mas "Marta dá Banco de Dados" se repete, porque Professor → Disciplina e Professor não é chave. A BCNF exige que todo determinante (lado esquerdo de uma dependência) seja chave candidata, que identifica a linha (WIKIPEDIA, [s.d.]): 

CREATE TABLE professor (
  professor  TEXT PRIMARY KEY,
  disciplina TEXT NOT NULL
);
CREATE TABLE matricula (
  aluno     TEXT,
  professor TEXT REFERENCES professor,
  PRIMARY KEY (aluno, professor)
);

O custo: o banco não impede mais que um aluno tenha dois professores da mesma disciplina (WIKIPEDIA, [s.d.]).

07 Limites

Normalizar nem sempre é melhor: mais tabelas exigem mais JOIN, e "não há obrigação de normalizar completamente" quando o desempenho conta (KENT, 1983, tradução nossa). Depois da BCNF vêm a 4FN e a 5FN (KENT, 1983; PROENÇA; MURANHO; PRATA, [s.d.]).
